# Задание 3

Приём вторсырья. Java 21, Spring Boot, JDBC и файловая реляционная БД H2. H2 устанавливается Maven вместе с зависимостями. Данные сохраняются в `data/recycling.mv.db`.

Пользователь сдаёт партию определённого вида вторсырья в пункт приёма. Пункт принимает несколько видов и имеет суточный лимит массы. С партией связана одна бонусная запись. Связи обеспечены внешними ключами; в БД запрещены отрицательные баллы, неположительная масса и повторный бонус на одну партию. При удалении родительских записей связанные партии и бонусы удаляются каскадно.

## Запуск из этой папки

В PowerShell задайте переменные (пароли выберите самостоятельно):
```powershell
$env:DB_USER = 'recycling_app'
$env:DB_PASSWORD = Read-Host 'Пароль приложения' -MaskInput
$env:DB_ADMIN_PASSWORD = Read-Host 'Пароль администратора БД' -MaskInput
.\mvnw.cmd clean package
java -jar target/student-api-0.0.1-SNAPSHOT.jar --spring.profiles.active=init
Remove-Item Env:DB_ADMIN_PASSWORD
java -jar target/student-api-0.0.1-SNAPSHOT.jar
```

Для Windows PowerShell 5 вместо `-MaskInput` используйте PowerShell 7 или задайте переменные окружения через настройки Windows. Нужен JDK 21 в JAVA_HOME/PATH. При последующих запусках задайте тот же DB_USER и DB_PASSWORD. Инициализация создаёт таблицы, ограниченного пользователя и начальные записи; повторять её обычно не нужно. Не меняйте рабочую папку: от неё зависит путь файла БД. Другой путь можно задать через DB_URL.

Приложение подключается пользователем с SELECT, INSERT, UPDATE, DELETE только для таблиц проекта. Создание таблиц и пользователей ему запрещено. Администратор используется только с профилем init. Пароли и файл БД не входят в Git.

## API

Для `users`, `recycling-types`, `collection-points`, `recycling-batches`, `bonus-entries` доступны GET списка, GET по id, POST, PATCH и DELETE под `/api`. POST возвращает 201, DELETE — 204. Время приёма задаёт сервер. Баллы рассчитываются как масса × баллы за килограмм.

Пять бизнес-операций:
- `POST /api/operations/accept` — принимает userId, pointId, typeId, mass; создаёт партию и ожидающий бонус. Проверяет доступность пункта, вид вторсырья и суточный лимит по UTC.
- `POST /api/operations/batches/{id}/credit` — начисляет ожидающий бонус принятой партии. Повторное начисление запрещено.
- `POST /api/operations/batches/{id}/cancel` — отменяет принятую партию и обнуляет её бонус, включая уже начисленный. Повторная отмена запрещена.
- `POST /api/operations/batches/{id}/transfer` с pointId — переносит принятую партию в другой доступный пункт с подходящим видом и свободным лимитом. После начисления перенос запрещён.
- `GET /api/operations/users/{id}/balance` — собирает баланс по пользователю, его активным партиям и бонусам: начисленные и ожидающие баллы.

Операции выполняются в транзакциях. Общая блокировка строки в БД сериализует запросы: параллельные приёмы не обходят лимит, повторное начисление не дублирует баллы. При ошибке изменения откатываются. Для учебного проекта такой способ проще, но ограничивает параллельность.

Импортируйте `requests.postman_collection.json` в Postman и запустите коллекцию по порядку. Она создаёт собственные записи, сохраняет id в переменные, выполняет CRUD и все бизнес-операции, проверяет отказ при повторном начислении и удаляет созданные данные. Начальные записи БД остаются.
